# 最小验收清单

本地验证：兼容层 505 项、服务层定向 59 项顶层测试通过。镜像证据见 `verification/RESULTS.md`。以下清单用于客户现场验收，尚未执行。

先在独立测试实例使用与生产相同的模型映射和 API 协议。现有 Harness、飞书 Bot 均继续直连 Sub2API，不增加新中间层。至少覆盖客户真实使用的每一种端点与流式模式。

| 场景 | 期望结果 |
| --- | --- |
| 只有 `reasoning_content` / `reasoning`、没有正文 | Responses 仅 reasoning；Anthropic 仅 thinking；无合成最终正文 |
| reasoning 后有真实正文 | 两类内容分离，最终正文只包含真实 `content` |
| reasoning 后调用工具 | 工具名称、调用 ID、参数保留；工具可正常执行并继续下一轮 |
| 达到输出 token 上限 | 保留 incomplete / max_tokens 状态和用量；不以 reasoning 冒充最终回答 |
| 正文含 `<analysis>示例</analysis>` / `<think>示例</think>` | 正文字面量原样保留，不误删用户需要的内容 |
| 多轮历史重放 | 结构化 reasoning 不被包装成标签后混入普通正文；工具结果能关联到原调用 |
| 非流式与流式 | 两者最终正文一致；流式正常结束，不串帧、不重复答案、不丢工具 |
| 正常空响应及普通回答 | 保留原有空响应兼容，普通回答可正常展示 |

再由客户确认实际链路：

- [ ] 每套实际使用的 Harness，至少跑普通问答、多轮与工具调用各一例。
- [ ] 飞书 Bot 的最终消息只显示应显示的正文；思考展示若启用，使用独立区域。
- [ ] 原 API 地址、模型名/路由、密钥、环境变量、端口和数据卷保持客户既定配置。
- [ ] 管理界面、认证、配额、计量、健康检查正常，未出现迁移错误。
- [ ] 记录测试时间、版本/镜像 ID、端点、模型映射、脱敏请求 ID和截图；客户明确确认通过。
- [ ] 已保留旧镜像和数据库升级前备份，能执行回滚。

若上游把思考直接放进普通 `content`，或客户端把结构化 reasoning 主动拼进答案，该用例不属于本补丁已解决范围。Claude 原生带签名 thinking 的完整重放也未在本包实现。不要把这类失败记录成“所有 Harness 已修好”。
